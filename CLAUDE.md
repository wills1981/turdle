# Turdle

Daily word-ladder puzzle: change one letter at a time to get from the start word to the target word.
Static site (`index.html`, `js/app.js`, `css/`) hosted on GitHub Pages from `main` / root, with no build step.
Run it locally with `docker compose up`, then open http://localhost:8080 (source is bind-mounted, so refresh to see changes).

## Layout
- `puzzles.txt`: the daily puzzle schedule (see below). `js/app.js` picks today's line by UK date (Europe/London),
  so the puzzle changes at UK midnight; the stats window counts down to it (`todayUK`, `msUntilUKMidnight`).
- `dictionaries/dictionary-N.txt`: every word accepted as a guess (SCOWL en_GB size ≤60).
- `dictionaries/common-N.txt`: everyday words (SCOWL ≤35). The game's solver (`findRoute`) routes through
  these for Par and Give Up, falling back to the full list only if needed.
- `tools/build_dictionaries.py`: regenerates both dictionary tiers from SCOWL. `tools/blocklist.txt` lists slurs removed from both.
- `tools/puzzles.py`: checks and generates `puzzles.txt`. **It holds the fairness rules; keep this file in sync with it.**
- `gen-puz/`: hidden puzzle helper (not linked; `noindex`). **One word**: list fair partners for a word (other word
  silly, everyday or either; tick Stretchy for different-length partners) and copy a `DATE|START|END` line.
  **Batch**: generate a date range, avoiding repeats of puzzles from a chosen date on (default 30 days back),
  optionally with stretchy Sundays/random days; Christmas days are kept. Its JS mirrors the rules in
  `tools/puzzles.py` (and `neighbours()` in `js/app.js`): keep them in sync.
- `tools/silly_words.txt`: the pool of silly start/target words the generator draws from.
- `tools/puzzles-3-letter.txt`: the 108 3-letter puzzles taken out of the schedule from 2026-11-17 (kept for reuse).
- `alerts.txt` + `images/`: a notice pop-up (`#modal-notice`, `loadNotice()` in `js/app.js`) shown when the game opens.
  Blocks are `KEY: "<html>";`, where KEY is a UK date (that day only) or a weekday like `FRIDAY` (every week).
  A dated notice wins over a weekday one. Comment out a block's first line with `#` to switch it off.
  `<img src>` is a filename under `images/` (subfolders allowed). Closing it hides it for the rest of the browser
  session (`sessionStorage` `turdle-notice`). The owner's HTML is trusted (it's our own file).
- `FEATURES` at the top of `js/app.js`: free play, hint and undo are currently switched off.
- `icons/og-<day>.png` + `s/<day>.html`: weekday link-preview images (BUMS, TIT, FARTY, GONAD, ARSE, TWAT, BALLS).
  Share links go to the puzzle's weekday page (`s/thu.html?p=2`), which sets that image and redirects to the game.
  `404.html` sends any unknown path (e.g. old `thu/?p=2` links) to the game, keeping the query.
  Both are generated by `node tools/make_og_images.js` (needs playwright-core); edit that, not the output.
- `audio-files/`: one clip per end state, played when the stats window opens at the end of a game: over par → `too-many-turns`,
  under par → `under-par`, on par → `thats-an-on-par-turdle`, gave up → `you-gave-up` (`SOUND_FILES`/`endState()` in `js/app.js`).
  The matching `turdle-crooner-banners/` image shows under the countdown, with a player under it (`#end-audio`: restart,
  play/pause, tap-to-seek bar). Tapping the banner also plays/pauses; taps play even when muted. Pause suspends the AudioContext.
  A hint under the player says when sound is muted, when autoplay was blocked, or (while playing, since device volume
  can't be read) to turn the volume up. `navigator.audioSession.type = 'playback'` lets it play through the iPhone silent switch.
  Players can mute the autoplay from the stats window (🔊/🔇, saved as `turdle-sound`).
- **Stretchy days**: any day whose start and target differ in length (detected automatically, no flag needed).
  Each turn may change, add or remove one letter; every word stays 3–7 letters (`STRETCHY_LENGTHS`), and guesses
  can be any length in that range. A rules banner (`#stretchy-rules`) shows all day, the badge reads `Stretchy 4➔6`,
  tiles show target matches (`tile-match`) and also mark the letter changed/added each turn
  (`tile-changed`; ringed teal when it's also a match), and the share grid
  marks target matches by position like normal days, each row at its own length. `replace` never touches stretchy days.
- Share text includes the 🟩/⬜ steps grid only if the player ticks "Include steps grid" in the stats window
  (off by default, as it hints at the route; saved as `turdle-share-grid`).
- "See yesterday's answer" (stats window) shows yesterday's par route, plus the player's own ladder from
  `turdle-past` (localStorage, last 7 daily games). Never reset `word_ladder_stats` or `turdle-progress`: they hold streaks.
- Streaks are date-aware: `word_ladder_stats.lastDaily` is the last daily counted. A replay of the same date is not
  counted again, and a missed day resets the streak. Stats from before `lastDaily` existed carry on untouched.
- Releasing a change to `js/app.js` or `css/styles.css`: bump the `?v=` on their tags in `index.html`, so an
  installed app never runs a new page against an old cached script. `sw.js` revalidates our own files on every load.
- Turdle Theme (header poo-quaver button, and the stats window once finished): plays/downloads
  `audio-files/turdle-theme-long.mp3`, with the lyrics written into `index.html`. The lyrics spell out puzzle #3's answer,
  so on that day only (`LYRICS_SPOILER_DATE`) they stay hidden until the puzzle is finished.
- Local preview: `localhost:8080/?date=YYYY-MM-DD` plays that day's puzzle (`PREVIEW_DATE` in `js/app.js`), with a red
  "PREVIEW · not saved" ribbon. Only on localhost/127.0.0.1 (ignored in production); saves nothing (no stats, streak or progress).
- `project_generator.py` is stale (old tiny word lists, old README). Don't run it, as it would overwrite the project.

## Populating puzzles.txt

### Format
```
# Date (YYYY-MM-DD) | Start Word | Target Word
2026-11-11|FIB|NOB
```
- One puzzle per day. Dates must be consecutive with no gaps or duplicates, in ascending order.
- Words are UPPERCASE, 3–7 letters. Normally the same length, 4–6 letters; different lengths make a stretchy day (3s only in the past schedule; 7s are allowed but none are fair). Lines starting with `#` are comments.
- A missing date falls back to a built-in schedule in `js/app.js`, so don't leave gaps.

### Theme
- Start and target words are silly and cheeky: toilet humour, body bits, smells, insults like GIT and NERD
  (e.g. FART, PANTS, POOP, BUMS, BURPS, WILLY, SNOT), or daft insults (DAFT, PLUM, WALLY, NITWIT).
- At least one of start/target must be silly; the other can be an everyday word from `common-N.txt`
  (the generator prefers both silly, 3:1).
- Cheeky is fine; hateful is not. Never use anything in `tools/blocklist.txt` or any slur.
- Mostly 4s and 5s, with a 6 now and then (`GEN_LENGTHS`). No new 3-letter puzzles. No 7s: with no shared
  positions they'd need par 7+, and no fair 7-letter pairs exist.
- Start/target words don't need to be common, or even in `dictionary-N.txt`: names are fine for fun, as the game
  always accepts the day's own start and target. `check` flags non-dictionary words (to catch typos) but doesn't fail them.

### Fairness rules (puzzles must not be so hard that players give up)
Enforced by `tools/puzzles.py check`; the constants live at the top of that file.
- **Par** (shortest route through common words): 5–8 from 2026-11-18 (`HARDER_FROM`), weighted toward 6
  (`PAR_WEIGHTS`). Earlier 4–6 letter puzzles were par 4–6, which felt too easy; 3-letter ones were 5–6.
- **No shared letter positions**: start and target never have the same letter in the same position
  (e.g. SPUD→SOCK is out). A green letter at the start is a bad experience. Puzzles before 2026-11-13 predate
  this rule and the 3-letter par minimum (`NEW_RULES_FROM` in `tools/puzzles.py`).
- **At least 2 distinct shortest routes**, so one wrong turn isn't fatal.
- **Route words must be everyday words**: the par route goes only through `common-N.txt`.
  Words that only connect via obscure words (e.g. EGGS needs ERGS, BREATH is a near-island) are out.
- **No repeats** (within `REPEAT_DAYS` = 30 days): a pair isn't reused, and a word appears at most twice.
  Older repeats are fine, as players will have forgotten. (The Python generator still avoids repeats file-wide.)
- **Stretchy days** use the same par/route rules, with routes through everyday words of any length 3–7.
  The no-shared-positions rule doesn't apply to them.
- Aim for the middle: the generator weights par 4 and 5 over par 6.

### Workflow
1. Extend the schedule (`--append` keeps existing lines; `--from` must be the day after the last line):
   ```bash
   python3 tools/puzzles.py generate --from 2027-01-01 --to 2027-03-31 --append
   ```
   Or edit `puzzles.txt` by hand for themed days (e.g. Christmas); `/gen-puz/` suggests fair partners for a chosen word, or generates a whole batch (incl. stretchy days).
   To swap out every future puzzle of some length (other days keep their words):
   `python3 tools/puzzles.py replace --from 2026-11-18 --lengths 4,5,6,7 --seed 18`
   `replace` never touches 25/26 Dec or 1 Jan (`KEEP_DAYS`), which are hand-picked Christmas puzzles.
2. **Always validate before committing:**
   ```bash
   python3 tools/puzzles.py check
   ```
   It prints par, the number of routes and an example route for each day, and exits non-zero if any rule is broken.
3. If the generator runs out of fair pairs, add words to `tools/silly_words.txt` and rerun.
4. Don't change today's or past puzzles once they're live; players may have already played them.
5. Puzzle numbers (#1, #2…) are days since 2026-11-11 + 1 (`FIRST_PUZZLE_DATE` in `js/app.js`), so never delete or shift past dates.

After rebuilding dictionaries (`python3 tools/build_dictionaries.py`), puzzles are rechecked automatically.
